# 任务提示词模板（DSH 14 字段）

> **用法**：实例化本模板，填成一份**具体任务计划**（鼓励这样做），再交给执行 Agent。
> 本文件是**字段定义的唯一出处**；其他文档只链接，**不复制模板定义正文**。
> 禁止的是"再造一份模板定义"，**不是**禁止填写任务实例。

## 0. 元数据（必填）

| 字段 | 值 |
| --- | --- |
| **Task ID** | `HEI-MA-YYYYMMDD-NNN-<LAPTOP\|AGX\|CANCEL\|DOCS>` |
| **任务名称** | 简短、可检索的任务标题 |
| **优先级** | P0 / P1 / P2 / P3 |
| **Owner（验收人）** | Codex |
| **执行 Agent** | DSH-LAPTOP / DSH-AGX |
| **状态** | TODO / PLANNED / DISPATCHED / RUNNING / REVIEW / TESTING / DONE / BLOCKED / FAILED / NEEDS_FIX / CANCELLED |
| **机器指纹** | 主机名、架构、工作目录绝对路径、DSH 版本、会话/终端标识 |
| **base SHA** | 开工前 `git rev-parse HEAD`；工作区状态（`git status --short --branch`） |
| **依赖** | 前置任务 ID、必需的环境/通道/授权 |
| **输入** | 需要读取的文件、数据、上游产物 |
| **输出（交付物）** | 明确的文件路径或报告结论 |
| **风险** | 可能踩到的硬件/数据/错误结论风险 |
| **权限范围** | 只读 / 指定白名单写入 / 无 |
| **硬件授权范围** | 默认：无。任何电机、运动、标定、固件、参数写入必须**逐项列出**并由用户明确授权 |

## 1. 背景

为什么做这件事；当前架构与主线（LeRobot + ZMQ；ROS 2 仅骨架）；相关历史结论及其证据等级。

## 2. 架构

本任务在整体中的位置；涉及哪些端、哪些进程、哪些数据流；是否触碰跨端契约（协议字段、单位、端口、坐标系、零位）。

## 3. 目标

可验证的目标陈述。若无法验证，改写目标而不是降低验收标准。

## 4. 环境

主机/架构/目录/base SHA/解释器（**明确说明 base ≠ 机器人环境**）/相关进程与端口/通信通道及其可达性现状。

## 5. 允许修改（白名单）

逐条列出允许新增或修改的**确切路径**。未列出即禁止。允许写入时说明可写范围（新增 / 追加 / 指定段落）。

## 6. 禁止修改（默认全集）与规则层级

**长期禁止（任何任务）**：修改未列入白名单的文件、破坏用户已有未跟踪文件、绕过安全联锁、
未授权访问硬件/凭据、未授权安装或联网。

**本次禁止**：本轮任务额外附加的限制（如"不改算法、不改环境、不安装、不联网、不访问硬件、不 commit"）。
⚠️ **必须显式标注为"本次约束"**，不要写成永久规则；后续任务按**用户授权 + 该任务白名单**重新确定范围。

**默认全集（未授权即禁止）**：其他仓库文件、机器人代码、环境与依赖、Git 分支/索引/提交/远端、
用户已有未跟踪文件、服务配置、驱动参数、标定；安装、联网、sudo、硬件访问、凭据读取。

## 7. 技术约束

必须保持的契约与边界（单控制源、18 维动作/三相机协议、单位、限位、看门狗语义等）；不得为省事绕过的逻辑。

## 8. 实施步骤

有序、可执行、每步可核查；标注"停下并报告"的条件。禁止把多个不相关操作打包。

## 9. 测试（分层）

逐级说明本任务**允许到哪一层**、以及具体检查命令。每级记录 **通过 / 失败 / 未执行 / 不适用** 与**证据**。

| 层级 | 名称 | 说明 |
| --- | --- | --- |
| L0 | 环境探针（可选附加） | hostname/架构/cwd/SHA/解释器版本/端口/标准库探针 |
| L1 | 静态 | 链接、`git diff --check`、语法解析、lint/类型 |
| L2 | 单元 | 无硬件依赖的单函数/单类测试（含假对象） |
| L3 | 模块集成 | 模块间接口、数据流、协议编解码往返 |
| L4 | 本地仿真 | MuJoCo 等纯仿真链路 |
| L5 | AGX 软件环境 | AGX 上依赖可导入、环境版本、构建产物 |
| L6 | 硬件非运动 | 只读设备枚举、串口/CAN 在线、限位 IO、参数读取（**不使能、不运动**） |
| L7 | 实机运动 | 使能、运动、回零、联调 —— **仅用户明确批准**，记录授权来源 |

**四类结论必须分开陈述**：代码实现 ≠ 仿真通过 ≠ AGX 部署 ≠ 实机通过
（**仅查版本不算 AGX 部署通过**；**L6 通过不等同于 L7 运动通过**）。

- **文档任务通常 L1**；**仿真任务按其目标执行 L2/L3/L4**；两者都**不要求**无关的硬件确认。
- 涉及运动的任务：L7 前置条件逐项满足并留证。
详见 [../MULTI_AGENT_WORKFLOW.md](../MULTI_AGENT_WORKFLOW.md) 第 10 节。

## 10. 交付

交付物路径 + 报告需包含的字段（见第 14 节）。报告应含**原始命令与退出码**，而非仅结论。

## 11. 验收

可核查的验收条件（由 Codex 判定）。示例：指定命令退出码为 0、指定文件存在、链接可解析、`git diff --check` 干净、tracked 文件零改动。

## 12. 异常处理

命令失败、平台不符、目录不符、工具不可达、权限被拒、输出截断时的**如实记录**要求；明确"先停下记录，不自行扩大 scope"。

## 13. Git 约定

分支/worktree 策略或明确记录的例外；只读要求；是否允许 commit/push（默认不允许）；需记录的 SHA 或文件哈希；严禁强推与硬重置。

## 14. 报告格式

执行 Agent 结束报告应包含：

- Task ID、主机/架构、绝对根目录
- Git 分支 / base SHA / **前后** `status`
- 环境与工具版本（路径 + 版本）
- **每条命令及退出码**、关键原始输出
- 探针类证据（如 `PROBE_OK`）原文
- 修改路径清单（新增/修改/未改动）
- **未验证项**与证据边界
- 状态结语：**等待 Codex Review**（不得自称验收通过）
