# 独立 Review 检查清单

> 使用者：**Codex**（独立于执行端）。执行 Agent 不得用本清单自证通过。
> 关联：[../MULTI_AGENT_WORKFLOW.md](../MULTI_AGENT_WORKFLOW.md) 第 9 节、[TASK_TEMPLATE.md](TASK_TEMPLATE.md)。
>
> **适用范围**：本清单服务于**未来的代码、仿真与集成开发任务**，不只是文档任务。
> 各节按任务类型取用：文档任务通常看 A/B/C/I/J/K；代码与硬件相关任务必须覆盖 D–H。
> **本轮"禁代码/禁环境/不 commit"是本次约束，不是永久规则**——不得用本轮口径限制后续任务。

**结果标记**：每条标 `PASS` / `FAIL` / `NOT_RUN` / `N/A`；标 `N/A` 必须写明**原因**。
`NOT_RUN` 与 `FAIL` 都必须进入结论，不得省略。

## A. 证据真实性

- [ ] **展开原始工具输出**核对，不依赖执行端的摘要或结论。
- [ ] 报告中的命令与退出码可追溯；失败命令已如实记录，未被静默省略。
- [ ] 探针类证据（如 `PROBE_OK`）为原始输出原文。
- [ ] 转义/编码内容已**解码后逐字比对**（避免 RF-001 类误读）。
- [ ] 未见"确认/已证明"用于仅有推断支撑的结论。
- [ ] 中断/取消类结论区分"界面显示在运行"与"确实收到开始输出"。

## B. 身份与环境一致性

- [ ] 主机名、架构、绝对根目录与任务要求一致。
- [ ] `git rev-parse --show-toplevel` 指向预期仓库。
- [ ] base SHA 与任务声明一致；HEAD 前后未变（除非任务允许提交）。
- [ ] 解释器路径与版本正确；未把 DSH base 环境当作机器人环境。
- [ ] 跨机任务：两台机器的 cwd/SHA/环境分别记录，未把一端结果当作两端结果。

## C. 改动范围与原有 dirty 保留

> 判据是**子集关系**，不是"完全相等"——任务允许在既有 dirty 工作区上增量修改。

- [ ] **任务新增差异 ⊆ 任务白名单**（逐文件核对）。
- [ ] **原有 dirty 状态完整保留**：原有 modified 文件未被回退；原有 untracked 文件未被删除或改写。
- [ ] 未出现白名单外的新增/修改/删除。
- [ ] 无分支切换、无 commit/push、无索引污染、无远端操作（除非任务允许）。
- [ ] 未安装依赖、未访问硬件或凭据（除非任务明确授权）。
- [ ] 空白与格式：`git diff --check` 无错误；**含新增 untracked 文件**的尾随空白也已检查。

## D. 代码正确性

- [ ] 逻辑与需求一致；边界条件（空输入、越界、极值）已考虑。
- [ ] **接口契约**：函数签名、参数含义、返回类型、错误返回与调用方一致。
- [ ] **数据结构**：字段名、顺序、类型、维度、单位与下游一致。
- [ ] **异常处理**：异常被捕获并处理或明确上抛；无静默吞异常。
- [ ] 资源生命周期：打开/关闭、连接/断开、分配/释放配对；异常路径也释放。
- [ ] 无复制粘贴遗留、无调试残留、无 TODO 冒充实现。

## E. 机器人契约

- [ ] **坐标系与 TF**：frame 命名、父子关系、变换方向与符号正确。
- [ ] **单位**：rad/m/mm 混用处已显式换算并标注；无隐含单位假设。
- [ ] **关节顺序与方向**：索引顺序、正负号、零位定义与协议一致。
- [ ] **IK 约束**：限位、可达性、解支连续性、目标拒绝逻辑未被绕过。
- [ ] 相机名称、字段顺序、编码（如 JPEG 包装）与协议一致。

## F. 安全

- [ ] **限位**：位置/速度/加速度限幅生效，且不依赖上层自觉。
- [ ] **急停**：软件停止路径明确；未把软件停止当作硬件急停。
- [ ] **超时/掉线**：通信超时、反馈断流、IO 离线时进入**由设备安全设计决定**的安全状态；
      **不得一概要求掉电/失能**（重力轴等场景掉电可能更危险），须说明该轴/机构的具体安全策略。
- [ ] **异常指令**：非法/越界/缺字段指令被拒绝，且按完整动作处理（不因缺字段默认为 0 而误动）。
- [ ] **上电与使能**：使能/失能顺序明确；异常退出按**该轴或机构经评估的安全策略**处置
      （如保持、制动、受控停止或安全失能），并**验证执行顺序**。
- [ ] 未绕过反馈检查、看门狗、解锁条件或安全联锁。
- [ ] 单控制源约束保持；连续运动类改动有额外风险评估。

## G. 维护性、日志与资源

- [ ] 命名与结构清晰；无顺手重构、无复制整套驱动的粘贴。
- [ ] **日志**：关键路径与异常有日志；无敏感信息入日志。
- [ ] **资源**：无句柄/线程/进程泄漏；长循环可退出。
- [ ] **并发**：共享状态有保护；无忙等；退出时线程/任务可回收。
- [ ] **依赖**：未新增未授权依赖；版本约束明确；导入不产生副作用。
- [ ] **测试**：新增逻辑有对应测试或明确说明为何不适用；现有测试未被削弱。

## H. 跨端与平台兼容

- [ ] **18 维动作接口**：维度、顺序、单位未变；缺字段处理符合约定。
- [ ] **三相机协议**：数量、名称、分辨率、编码、时间戳一致。
- [ ] **ROS 2 骨架**：未把规划中的 ROS 2 能力描述为已实现；接口方向（数据/TF 先行）符合规划。
- [ ] **ARM64 兼容性**：无 x86 专用二进制/指令假设；依赖在 aarch64 可得。
- [ ] 双端共享的协议/配置改动已评估对另一端的破坏性。

## I. 文档类专项

- [ ] 新增文件路径与数量与授权一致。
- [ ] 所有相对链接可解析（目标文件真实存在）。
- [ ] Mermaid 代码块语法闭合、与正文描述一致。
- [ ] **模板定义只维护一份**（TASK_TEMPLATE.md）；**允许实例化填写任务计划**，不得另抄一份模板定义。
- [ ] **规划内容与已实现内容明确区分**；未由"本轮未执行"推断"项目未实现"。
- [ ] 历史快照段落未被改写；更正以**追加**方式记录。
- [ ] 状态机与状态取值在各文件中一致。
- [ ] 跨机同步状态已注明（文档默认只存在于实施端）。

## J. 安全与授权

- [ ] **每个任务都写清了硬件的允许/禁止范围**；无授权即未进行硬件访问。
- [ ] 若任务声明为"本次初始化全部禁止硬件访问"，则实际**无任何硬件访问**。
- [ ] 未出现超出授权的使能、运动、标定、固件、参数写入等操作。
- [ ] **L6（硬件非运动，普通只读核查）按该任务已有授权执行**，未被要求重复逐项确认。
- [ ] 使能、运动等**危险操作有用户明确授权**的记录，且**未绕过任何安全联锁**。
- [ ] 未绕过沙箱或索取更宽权限。
- [ ] 输出中无 token/私钥/证书/完整用户历史。

## K. 结论强度

- [ ] 静态检查未被表述为功能验收。
- [ ] **代码实现 / 仿真通过 / AGX 部署 / 实机通过**四类结论分别列出，未互相代替。
- [ ] 分层测试每级记录了**通过/失败/未执行/不适用**及证据。
- [ ] 未宣称全平台或实机验证通过。
- [ ] 未验证项被明确列出，而非省略。
- [ ] 报告以"等待 Codex Review"结尾，未自称 DONE。

## L. 复审

- [ ] 每个 finding 有编号、优先级、证据与要求动作。
- [ ] 执行端更正后，**复审**并记录接受/拒绝结论。
- [ ] 更正不覆盖原始错误记录（保留可追溯性）。
